2. CRAD academic pipeline

Capstone / thesis work is a gated chain. Later steps are blocked until earlier records exist (registered group, assigned adviser, approved chapters, scheduled defense).

  1. Title proposal. Student submits CRAD Form S2 (Title Approval) in Student Portal → Research Proposal (modules/student-portal/pages/research-proposal-submission.php). If the title was Returned, the sidebar opens the returned-title notification instead of a blank form.
  2. Triple sign-off. Adviser, Research Coordinator, and CRAD Officer must all approve, with stored signature data. See Section 3.
  3. Register proposal. CRAD Officer registers the title (registration_status: Pending → Registered) in Register Proposal.
  4. Research group number. Official group number is issued (research-group-number.php).
  5. Assign adviser. Department Head retrieves approved research, checks availability, and assigns an adviser.
  6. Research development. Student uses My Research, Research Plan, Milestones, Progress Updates, Adviser Feedback. Adviser monitors the same group from the faculty workspace.
  7. Submit Chapters 1–3. Student uploads documents. Grammarian scores five criteria at 20% each (content, methodology, references, format, grammar).
  8. Pre-oral defense scheduling. Research Director (or operational Admin) queues groups that have approved Chapters 1–3, proposes slots (max 3 panel members), and finalizes venue/time.
  9. Panel evaluation. Assigned panel members score the defense (Evaluation & Scoring).
  10. Implementation / Chapters 4–5. Student continues milestones (system development, testing, documentation) in 2nd semester phase.
  11. Final manuscript. Student uploads versions; CRAD / adviser review and revision compliance.
  12. Final defense. Director schedules Final Defense; panel uses Final Defense Evaluation.
  13. Revisions. Adviser tracks Final Defense Revisions / Revision Monitoring.
  14. Research clearance. Student uploads collage/college payment and the signed clearance image. CRAD Officer approves or rejects from the clearance inbox.
  15. Repository / Publications & IP. Completed work is recorded and archived.

3. Official title / group rule (integrity gate)

A research group is treated as official only when all of the following are true on crad_title_approvals:

  • status = 'Approved'
  • coordinator_status = 'Approved'
  • crad_status = 'Approved'
  • Adviser, coordinator, and CRAD signature fields are non-empty

Implemented by cradValidTitleApprovalWhereSql() in modules/crad/config/config.php. Department Head “Retrieve Approved Research” and registry queries reuse this rule.

4. Grant funding pipeline (parallel track)

Researchers (student or adviser) apply from Grant Opportunities. Scoring happens in Reviewer Evaluation. Funding then requires six sequential office signatures. A step cannot be skipped. Choosing NO sets status Returned; the applicant sees it under Revisions Requested and the chain restarts.

7.9 Operational Admin (sms_admin)

getVisibleModules() replaces every module with a CRAD-only workspace:

  • Approval Clearance Payment, Dashboard & Analytics, Grant Opportunities, Proposals & Applications
  • Full pre-oral and final defense scheduling (same director views)
  • Announcements (granted-admin extra)
  • Security via Profile → Security tab

7.10 Super Admin · User Management only

  • User Accounts — create, lock, assign roles
  • Role & Permissions — sms2_role_permissions matrix
  • Module Security — password-reset approvals, per-module logs
  • Activity Logs — sms2_activity_logs
  • System Settings — idle timeout, CAPTCHA/Turnstile, maintenance

Hard rule: Super Admin is stripped of crad and crad_grant in smsAllowedModuleKeysForRole().

8. Security features and proof

For defense: show the UI first, then name the file. Every row exists in this repository.

FeatureHow it is seen in the running systemCode proof
Login required Opening a module while logged out redirects to login/login.php. AJAX/API calls receive JSON 401 session_expired instead of HTML (avoids fake “success”). requireAuth() in includes/authentication.php
Role-based modules (RBAC) Student never sees User Management. Super Admin never sees CRAD. Sidebar is built from allowed modules only. smsAllowedModuleKeysForRole() + table sms2_role_permissions; students forced to student_portal only
Page-level role gates Pasting another role’s URL shows Forbidden or a redirect, not the page. Examples: submit-chapters.php requires student; CRAD clearance uses rscCanManageAsCrad(); director uses smsCanManageDefenseScheduling(); grammarian uses chapterIsEvaluator()
Password hashing Sign-in form. Failed login does not reveal whether the username exists (dummy password_verify on unknown user). password_verify against password_hash; dummy hash path in authentication.php
CAPTCHA / Cloudflare Turnstile Checkbox or Turnstile widget on Sign In, evaluated before password and 2FA. includes/captcha.php; login.php: CAPTCHA first so bots never reach password check
Passkey (WebAuthn) “Sign in with passkey” on login; enroll under Security Settings. includes/passkey.php, assets/js/passkey.js, api/passkey.php, table sms2_user_passkeys
Authenticator TOTP + email OTP Security Settings / Profile: enable Google Authenticator; 6-digit codes. Password change requires Authenticator or email OTP. includes/totp.php; smsCreateOtp() / smsVerifyOtp(); sms2_security_otps stores SHA-256 of the code
Login throttle / lockout After too many failures, Sign In is disabled until cooldown; wait time is shown. sms2_login_throttles; smsLoginGateSet() / smsLoginGateStatus()
Force password change After an admin reset, next login goes to Change Password. must_change_password column and session flag → login/change-password.php
CSRF tokens Hidden csrf_token in forms. Invalid token shows “Security check failed.” csrfToken() / csrfVerify() using hash_equals in includes/security.php
Session hardening + idle logout Cookie name SMS2SESSID. After idle time, overlay then redirect to login.php?timeout=1. config/session.php: HttpOnly, SameSite Lax, Secure on HTTPS, session.use_strict_mode; smsEnforceSessionTimeout(); assets/js/idle-logout.js
Security headers + CSP Browser DevTools → Network → response headers on any page. smsSendSecurityHeaders(): X-Frame-Options SAMEORIGIN, X-Content-Type-Options nosniff, CSP default-src self (+ Turnstile)
Prepared SQL statements Not a visible widget; identity lookups still use bound parameters. PDO prepare / execute throughout CRAD helpers and sidebar queries
HTML escaping User-supplied titles and names render as text, not HTML. e() → htmlspecialchars(..., ENT_QUOTES)
Secure file uploads Chapter / clearance upload accepts PDF/DOC/images only; files are not directly executable from the web. includes/uploads.php: MIME + extension whitelist, random stored names, storage/uploads/.htaccess Deny from all
Secrets encryption at rest System Settings stores Turnstile / SMTP secrets; they are not shown in plaintext after save. includes/crypto.php AES-256-GCM; TOTP secrets in sms2_user_authenticators
Activity audit log Super Admin → Activity Logs; also Security Settings module logs. Failed logins are recorded. logActivity() → sms2_activity_logs (user, role, action, IP, user agent)
Maintenance lock Public users hit the maintenance page; admins use ?access=admin. smsEnforceSystemMaintenance() / smsIsModuleInMaintenance()
Title approval integrity Group is not official until three statuses and three signatures exist (Section 3). cradValidTitleApprovalWhereSql()
Grant sequential signatures Approval Workflows: only the current office can YES/NO; NO returns the proposal. grantApprovalStepDefinitions() and step-ownership checks
Password reset workflow Staff request a reset; Super Admin approves in Module Security. sms2_password_reset_requests (pending / approved / rejected)

9. Limitation to disclose

The student sidebar “Research Forum paid” lock still uses a hardcoded sample payment list in includes/sidebar.php, not a live ledger query. Do not claim that lock is production-complete unless it is wired to Payment History.
